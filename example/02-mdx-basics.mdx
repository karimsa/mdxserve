# MDX Basics

This file ends in `.mdx`, but to `mdxserve` that makes no difference: `.md` and `.mdx` are
parsed, validated and rendered the same way. Either extension can use the builtin components,
a small set of lowercase HTML elements, and literal values in curly braces, all inside what
otherwise reads like a normal Markdown document.

One consequence worth knowing: MDX is stricter than plain Markdown. A stray `{` or an unclosed
`<tag>` in prose is a syntax error rather than literal text, so escape them as `\{` or wrap them
in backticks. A bare `<` before a digit, a space or `=` (as in "a < b") is fine.

## Lowercase elements

A few HTML elements cover what Markdown has no syntax for. Press <kbd>Ctrl</kbd> + <kbd>C</kbd>
to copy, write H<sub>2</sub>O and E = mc<sup>2</sup>, <mark>highlight</mark> a phrase, or
spell out <abbr title="Model Context Protocol">MCP</abbr> on hover.

<details id="more-details">
  <summary>Show the supported elements</summary>

`kbd`, `abbr`, `sub`, `sup`, `mark`, `b`, `i`, `u`, `s`, `em`, `strong`, `small`, `br`, `span`,
`details`, `summary`, `table` (with `thead`, `tbody`, `tr`, `th` and `td` inside it), `a` and
`img`. Other tags are unwrapped, and `className`, `style` and event handlers are dropped.

</details>

## Literal values

Curly braces hold a literal value: an array, an object, a string, a number, a boolean or null.
In a prop it is passed as is, like the `values` of this sparkline:
<Sparkline values={[3, 5, 4, 8, 6, 9]} />. In prose, a string or number shows as its text
({"like this"}), an array or object as its JSON ({[1, 2, 3]}), and `true`, `false` and `null`
show nothing.

Anything else, such as `{1 + 1}` or an `import`, is not run: `mdxserve validate` reports it with
the change that fixes it, and the rest of the page still renders.

## Why this matters

Write whatever reads best as Markdown, and reach for a builtin only when it presents something
better than prose. See [`06-builtins.mdx`](./06-builtins.mdx) for the full tour of builtins.
