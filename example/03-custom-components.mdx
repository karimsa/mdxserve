# Custom components

MDX files can import and render ordinary React components, not just built-in HTML elements.
The import at the top of this file pulls in `Counter.tsx` from the `components/` folder next
to this document.

## How component resolution works

- Components are plain `.tsx` files, written like any other React 19 component.
- Vite resolves the `import` paths relative to this MDX file, exactly like it would in a
  normal `.tsx` module. There's no special "components folder" convention required — you
  could import from anywhere Vite can resolve.
- Imports are explicit. There's no auto-registration or global component list for your own
  components: if a component isn't imported at the top of the file, it isn't available in
  the document.
- `react` itself is provided by `mdxserve` — you don't need to `npm install react` in your
  docs folder for this to work. You only need to install packages if a component you write
  depends on something beyond React itself.
- The one exception is `mdxserve`'s **builtin components** (like `Callout`, used below):
  those are always available, with no import needed — see `06-builtins.mdx`.
