# Builtin components

`mdxserve` ships a small library of components that are available in every `.mdx` file with
no `import` — they're registered globally, the same way `pre` and `figure` are overridden for
code blocks. If you `import` your own component with the same name in a file, your local
import wins.

## Diff

<Diff
  title="server.ts"
  language="ts"
  before={`const server = http.createServer(handler);\nserver.listen(3000);\nconsole.log("listening");`}
  after={`const server = http.createServer(handler);\nconst port = Number(process.env.PORT ?? 4040);\nserver.listen(port);\nconsole.log(\`listening on \${port}\`);`}
/>

`Diff` renders a GitHub-style diff between `before` and `after`, with a pill to switch between
the unified view above and a side-by-side split view, and a copy button that copies `after`.
Same-length removed/added blocks get intra-line highlights when the changed portion of the
line is small enough to be worth marking.

With a longer snippet, unchanged runs longer than `2 * context` (or just `context` at the very
start/end) collapse into a clickable separator — set `context={1}` here to make that show up
with only two small, far-apart changes:

<Diff title="config.yaml" context={1} before={longBefore} after={longAfter} />

```mdx
<Diff
  title="server.ts"
  language="ts"
  before={`const server = http.createServer(handler);\nserver.listen(3000);\nconsole.log("listening");`}
  after={`const server = http.createServer(handler);\nconst port = Number(process.env.PORT ?? 4040);\nserver.listen(port);\nconsole.log(\`listening on \${port}\`);`}
/>
```

## Dropdown

`Dropdown` is a button that opens a menu. Give it `options` for a plain picker:

<Dropdown label="Theme" options={[{ value: "system", label: "System", description: "Follow the OS setting" }, "Light", "Dark"]} />

`options` takes strings, or `{ value, label }` pairs when the value should differ from the
label (and an optional `description` line); add `size="sm"` for the 28px control.

Give it `Option` children instead and it becomes a content switcher — the menu picks which
option's content renders below, cross-faded:

<Dropdown label="Install on">
  <Option label="macOS">
    ```bash
    brew install mdxserve
    ```
  </Option>
  <Option label="Linux">
    ```bash
    curl -fsSL https://mdxserve.dev/install.sh | sh
    ```
  </Option>
  <Option label="Windows">
    ```powershell
    scoop install mdxserve
    ```
  </Option>
</Dropdown>

Prefer `Tabs` when there are only 2-4 visible alternatives; reach for `Dropdown` once the list
of options gets longer than fits comfortably as tabs.

## Discovering builtins from the CLI

The same metadata that describes each builtin — its props, defaults, and when to use it — is
published as a JSON registry at build time, and can be queried from the command line:

```bash
# List every builtin component
mdxserve components search

# Search by name, description, or prop
mdxserve components search callout

# Show full details for one component, including a props table
mdxserve components show Callout

# Get the raw registry entry as JSON (handy for tools/AI agents)
mdxserve components show Callout --json
```

This is the same registry an AI coding agent can query to find out what components are
available before writing docs for you.
