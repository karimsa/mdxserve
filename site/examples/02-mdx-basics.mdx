	title: "MDX Basics",

# {meta.title}

This file ends in `.mdx`, but to `mdxserve` that makes no difference: `.md` and `.mdx` are
compiled through the same MDX pipeline. Either extension lets you export values, write inline
JSX, use the builtin components, and drop in JavaScript expressions wrapped in curly braces,
all inside what otherwise reads like a normal Markdown document.

One consequence worth knowing: MDX is stricter than plain Markdown. A stray `{` or an unclosed
`<tag>` in prose is a compile error (shown in the page) rather than literal text — escape them
as `\{` or wrap them in backticks.

The `export const meta = {...}` block above isn't rendered — it defines a plain JS object you
can reference later in the file, like the page title just did with `{meta.title}`.

## Inline JSX

You can write JSX directly in the middle of Markdown content:

<div className="rounded-lg border border-neutral-200 dark:border-neutral-700 p-4 my-4">
	This box is a plain `div` with Tailwind classes, written as JSX inside an `.mdx` file.
</div>

## JS expressions

Anything in curly braces is evaluated as JavaScript. For example, `1 + 1` is {1 + 1}, and the
page title from the `meta` export above is "{meta.title}".

You can also use expressions inline, like today being day number {new Date().getDate()} of the
month — this is re-evaluated every time the page renders.

## Why this matters

Write whatever reads best as Markdown, and reach for JSX only when you want to embed
interactive components or compute something inline. See
[`03-custom-components.mdx`](./03-custom-components.mdx) for importing real components instead
of writing raw JSX by hand, and [`06-builtins.mdx`](./06-builtins.mdx) for the components that
need no import at all.
